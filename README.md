# CoverFit

图片格式转换 + 比例裁切，纯浏览器本地完成。

**https://cool-zimo.github.io/coverfit/**

## 能做什么

- **格式转换**：PNG / JPEG / WebP / GIF / BMP / ICO / AVIF
- **比例裁切**：11 种预设 + 自定义，裁切框可拖可缩放
- **尺寸控制**：原尺寸 / 限制最大边 / 指定宽度
- **有损质量控制**：JPEG / WebP / AVIF 可调
- **批量**：一次拖入多张，逐个处理，也能一键全部导出

## 怎么用

把图片**拖进页面**，或者点「选择文件」，或者直接 `Ctrl+V` 粘贴。

选中比例 → 拖裁切框调整范围 → 选格式 → 下载。

## 关于隐私

图片**不会上传到任何服务器**，解码、裁切、编码全在你自己的浏览器里完成。
断网也能用（首次打开之后）。

## 一些实现上的细节

**为什么 BMP 和 ICO 要自己编码**
`canvas.toBlob()` 不支持 ICO，BMP 也只有部分浏览器支持。不自己实现的话，
选这两种格式会静默失败——按钮点了没反应，或者下载下来是个 PNG 却叫 `.ico`。
两者的编码都做了单元测试，并用 Pillow 反读验证过像素。

**透明转 JPEG 会变黑**
PNG 有透明通道，JPEG 没有，直接导出透明区会变成黑色。
导出 JPEG 前会先铺白底。

**手机照片的方向**
竖拍的照片文件里其实是横着的，靠 EXIF 标记旋转。
解码时显式指定 `imageOrientation: 'from-image'`，否则人会躺下。

**格式可用性是探测出来的**
不是查浏览器型号，而是拿 1×1 画布实际编码一次看结果——
`toBlob` 在不支持时会**静默退化成 PNG**，只看有没有返回值是发现不了的。
当前浏览器不支持的格式会直接禁用并说明原因。

## 本地运行

纯静态，没有构建步骤，也没有依赖：

```bash
python3 -m http.server 8000
```
